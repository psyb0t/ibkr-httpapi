# HTTP API conventions

- **Routing**: every REST path is declared in `api/v1.yaml`. `make generate-api` turns it into one `APIRouter` per tag under `ibkrapi/api/_generated/routers/` (`system`, `stocks`, `options`, `futures`, `cfd`, `forex`, `crypto`, `orders`, `history`). `ibkrapi/server.py` mounts all of them under the fixed `/v1` prefix. Spec paths stay unversioned; the prefix comes from `servers.url`. The MCP app is mounted at `/mcp`, outside `/v1`.
- **Path shape**: `/<asset_class>/<symbol>/...` (forex uses `{pair}`) plus the cross-asset `/orders`, `/positions`, `/account`, `/account/values`, `/accounts`, `/history/executions`, `/history/completed_orders` and `/ping`.
- **Auth**: bearer token in `Authorization: Bearer <token>`, checked by the `_log_and_auth` middleware for every path, `/v1/ping` and `/mcp` included. The token comes from `--token`, then `API_TOKEN`, then `config.yaml:api_token`. Empty means open access.
- **Error envelope**: `{"code": "UPPER_SNAKE_CASE", "message": "...", "details": {...}}`, built by `ibkrapi.errors.error_response()` or raised as `APIError`. Codes live in `ibkrapi/errors.py`; add a new one there and in the docs error table.
- **Status codes in use**: 400 `BAD_REQUEST` (bad bar size, order rule), 401 `UNAUTHORIZED`, 404 `NOT_FOUND` (contract, order or account), 422 `VALIDATION_FAILED` (FastAPI validation), 429 `RATE_LIMIT_NEAR` (pacing gate), 500 `INTERNAL_SERVER_ERROR` (uncaught exception), 502 `UPSTREAM_FAILED` (wickworks error, empty IBKR tick), 503 `TA_SIDECAR_UNAVAILABLE` (wickworks URL unset or not http(s)). `GATEWAY_UNAVAILABLE` is defined but nothing raises it: `ibclient.get_ib()` keeps retrying until the gateway answers, so a request waits instead of failing.
- **Request bodies**: every POST body is a Pydantic v2 model generated from the spec into `ibkrapi/api/_generated/models.py`. Query params are explicit in the spec.
- **Response shape**: a top-level object, never a bare list. Bars, ticks, trades, fills and contracts sit under a named key (`"bars"`, `"ticks"`, `"trades"`, `"fills"`, `"contracts"`).
- **Pagination**: none. IBKR returns capped result sets.
- **Mutating routes** (`POST /orders`, `POST /options/combo`, `POST /options/exercise`, `DELETE /orders`, `DELETE /orders/{orderId}`) act on a real brokerage account. Their MCP tool descriptions say so; keep that wording when you touch them.
